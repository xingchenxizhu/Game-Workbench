# 开发说明

本文保留架构与维护约束，功能与安装步骤以 [README](../README.md) 为入口。第三方素材模块的约束见 [AGENTS.md](../modules/material/AGENTS.md) 和 [工程文档](../modules/material/docs/ENGINEERING.md)。

## 共享核心与双形态

网页服务和 DSH 插件共用 `src/server/host.ts` 的 `createWorkbenchHost()`。网页模式通过 `standalone.ts` 启动，DSH 通过插件入口注册 `/game-workbench/` 前缀。客户端 URL、静态资源、下载和回填接口必须兼容此前缀。

浏览器 SPA 位于 `src/client/`；工具入口由 `registry.ts` 注册，参数驱动的生图流程由 `flows.ts` 定义。新工具优先复用 `views/kit.ts`、画布算法和公共导出接口。

## 工作区与任务

每个工作区使用独立素材 Worker、配置和项目目录。默认工作区沿用 `data/dsh`，新工作区使用对应的 `workspaces/<id>/dsh`。API Key 使用原模块的保存与遮罩机制，不在页面中回显完整密钥。

切换工作区前保存草稿；执行生成、上传或媒体处理时应阻止切换。跨工作区清理客户端缓存和旧轮询，拒绝旧页面写入其他工作区。

设置和地图工程采用临时文件与原子替换。图片任务按 ID 保存，取消、完成和阶段更新需要串行处理，避免旧事件覆盖终态。重启后的未完成任务应明确标记中断，不能静默重试可能产生费用的请求。

## 页面与导出

原生工具缓存编辑节点，素材 iframe 保持在持久容器中；普通导航不应重载 iframe 或丢失草稿。离开页面要释放订阅，后台刷新不得覆盖用户正在编辑的提示词。

导出复用工作区素材位置，同时提供浏览器下载。图片、图集和工程输出应带清楚的规格及完整性信息；未生成素材不能标记为完整资产包。

PSD 为栅格图层导出，位置、旋转和缩放会烘焙为像素；不包含文本层或智能对象。继续编辑原始变换需要保存工作台工程。RPG Maker 角色表按已有帧整理，不猜测朝向或补帧。

## 构建与验证

```powershell
npm ci
npm run build
npm run typecheck
npm test
npm run check:ts
npm run check:plugin
```

`src/client` 编译到 `public/`，`src/server` 和插件入口编译到 `lib/`。不要只改编译产物。`modules/material` 有独立构建流程，按该模块的说明执行。

可选界面检查：`check:ui`、`check:production`、`check:stitch`、`check:auto-image`。测试结果写入本地 `test-results/`，不提交到仓库。真实生图检查 `check:image-live` 会消耗当前账号用量，应显式执行。

模拟接口、文件结构检查、真实浏览器操作、模型生成和真实 DSH/游戏引擎运行属于不同验证层级，不可互相替代。不要把历史测试数量或已移除的本地报告当作当前版本验收结果。

## 参考来源与范围

完整多轨视频、3D 地形、模型减面和 UV 烘焙不属于当前已交付能力。各导出引擎包仍需在目标引擎中验收。
