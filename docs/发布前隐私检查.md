# GitHub 发布前隐私检查

源码、lib/、public/、package-lock.json、项目技能及第三方许可证属于发布内容。lib/ 和 public/ 是 DSH 直接加载的产物，不能当作缓存全部删除。

## 不提交的内容

- data/：API Key 配置、任务提示词、参考图、结果、视频、工作区路径、备份。
- 测试的素材/、test-results/、artifacts/：个人输入、截图、测试产物与旧压缩包。
- node_modules/、日志、缓存、数据库、环境变量文件、私钥、认证状态和本地配置。
- 同级目录中的本地私有备份，不能一起上传。

项目中的来源记录只保留相对路径。测试示例为程序生成的无个人元数据网格，不包含用户生成素材。原第三方许可证和署名保留，不应误删。

## 上传方式

请在本项目根目录创建 Git 仓库，并使用 Git 提交。不要拖拽整个文件夹到 GitHub 网页上传：网页上传或第三方压缩工具不会自动遵守 .gitignore。

```powershell
git init
git status --short --ignored
git add .
git diff --cached --stat
git diff --cached
# 检查完成后再 commit / push
```

.gitignore 仅影响未跟踪文件。如果以前提交过密钥或素材，需要从索引及历史记录中移除；已公开过的密钥必须在供应商处撤销和重新生成。

修改后需重新执行隐私检查；任何自动扫描都不能保证识别所有敏感内容。运行数据保留在本机，但不属于公开仓库。发布 npm 包时另有 .npmignore 排除规则。
